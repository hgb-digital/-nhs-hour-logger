## Description

This logger was created to centralize all NHS organization into one website. This logger, however, never reached deployment due to strict FERPA guidelines, which place strict limitations on the hosting of student information. Although I made multiple efforts to work with our local district IT, we never reached an agreement. This logger serves as a template for an organizational volunteer web app, proving viability of future use with local volunteer organizations (especially since it's lightweight).

## Development

To develop this web app, I ran a XAMPP development web server (including Apache and a MySQL database) and coded using Visual Studio Code. I mainly used Claude for research purposes, helping me to continue to learn the languages (PHP, HTML, CSS, JS, MySQL) and brainstorm technical workarounds. Throughout the process, I met with my chapter advisor to discuss the future direction of development in order to fit the needs of the organization.

A MySQL configuration file for the NHS database exported from phpMyAdmin (a database management application) is also included in this repository. The majority of the information included in that database was generated by Claude as filler data so I could see how it would look while in use.

## Features

Users can log in, log hours, sign up for service opportunities, and see hour statistics per committee. At my high school, we have 4 committees within NHS (everyone is a member of one) that each focus on differing avenues of service. Officers can also create service opportunities (title and description) and add as many roles as needed. Roles can have a title, a time of service, an attire, and a set number of signup slots. 

When logging hours, users can add either Individual Service Projects (ISPs) or Group Service Projects (GSPs). Individual hours require a supervisor, while group service hours require you to have been signed up on the service sheet prior to the date of service. Officers can also remove hours they feel are malicious or incorrectly documented. For account verification and password resets, the website can send emails to users through PHPMailer and SMTP2GO.

## Process / Structure

This project was developed over 2 weeks and, alongside other projects, was uploaded to GitHub for the MIT Maker Portfolio and therefore has minimal version control. However, below I have outlined the development process so reviewers can specifically see how the project evolved over time. Information regarding development will also be provided in the media upload of the MIT Maker Portfolio.

### PHASE 0
In April 2026, before starting the project, I met with my chapter advisor to see if an NHS website would be used and got approval to start development.

### PHASE 1
For this project, I began by using the same login/signup system (that includes password hashing) along with the basic structure for a website that I used in the Eversole Network project (see other projects). This structure worked as follows:

* **File Segmentation:** Project files are split into 2 folders: `htdocs` and `private`. The `htdocs` folder was the web root and was what web users physically had access to from the internet. However, in order to create a secure environment, I moved the majority of the project's files into a private folder (inaccessible to web users). The `index.php` in `htdocs` would then check the URL the user inputted (or was directed to) and ensure the file they were trying to reach was accessible with the permissions assigned at login. For this project, I checked if the user was logged in before allowing access. Admin- or officer-specific pages had a permission check at the top of the file to redirect unauthorized users.
* **File Organization:** In the private folder, files were split into groups based on function:
  * `pages/all_access`: Contained pages accessible via URL (through `index.php`).
  * `scripts/features`: Contained PHP `$_SESSION` config and shared utility scripts.
  * `scripts/login` & `scripts/signup`: Authentication handling.
  * `scripts/view`: UI resources (tables, images, messages, or CSS; see `serve_resources`).
  * `scripts/web_management`: Scripts accessed using POST requests (see `handle_POST`).
* **Database Queries:** The `dbh_manager.php` file (in `/private`) handled all database queries. Scripts called the `run_query()` function to interact with the database. For security, this file used prepared statements with bound parameters to prevent SQL injection vulnerabilities.
* **handle_POST:** Because backend scripts in the private folder cannot be directly accessed by HTML form actions, `handle_POST.php` in the public `htdocs` directory acted as an entry barrier. Any POST request was routed here first to verify that the user had sufficient permissions before proceeding.
* **serve_resources:** Allowed HTML files to securely reference CSS, JS, and image assets stored inside the restricted private folder (`/private/view/resources`).

### PHASE 2
I altered the previous architecture to fit the needs of the NHS. This included modifying user permissions enumerations in the database, creating hour log/signup sheet tables, and updating colors and text to match NHS branding.

### PHASE 3
Active development began with the hour logging system to support both individual (ISP) and group (GSP) hours. The Log Hours page displays:
1. ISP vs. GSP hours logged statistics.
2. A toggle section allowing users to submit new individual or group hours.
3. Summary lists of previously logged hours with the option to remove them.

### PHASE 4
Group hour opportunities require a signup sheet so organizers know who to expect and officers can verify attendance before hours are logged. Members can view upcoming/past volunteer opportunities on the Group Service page and sign up or remove their names. Officers can create these signup sheets with custom roles and slot limits. To prevent forgery, users can only log group hours for opportunities where their name appears on the signup sheet (selected via a pre-populated dropdown).

### PHASE 5
In this phase, I implemented features allowing members to view a directory of NHS members and their logged hours. Officers received the ability to delete malicious entries. Using Claude, I implemented an hour chart displaying total hours logged per committee. Finally, an email verification and password reset system using PHPMailer and SMTP2GO was integrated using temporary tokens sent via email links.

### PHASE 6
Development concluded after the functional prototype was complete. Production deployment was halted when the local IT department denied permission to host student data due to FERPA compliance constraints. Attempts to negotiate hosting via an IT-approved provider (AWS) were ultimately unapproved.
